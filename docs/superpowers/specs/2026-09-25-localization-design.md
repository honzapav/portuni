# Localization: English default, Czech second

The UI, the server's human-facing text and the desktop shell speak the
user's language: English by default, Czech on request. The language is
a property of the user, set under Settings → Account, and follows them
to every device.

## Scope

| Surface | Language |
|---|---|
| Web UI (all screens, gates before `App`, error overlay, confirms) | user's |
| REST / WebSocket errors shown to the user | user's, rendered by the web from a code |
| Runner events shown in the chat (question titles, errors) | user's, rendered by the web from a code |
| Handoff summary file, default thread name | user's |
| OAuth consent and login error pages (server-rendered) | user's if known, else browser's |
| Desktop: `Quit` menu item, loopback login page, Rust errors | user's (window's) |
| Agent-only text: system prompt, orientation, resume/handoff sections of the prompt, MCP tool descriptions and resources, `PORTUNI_SCOPE.md`, marker blocks | always English |
| Content: node names, file contents, user and agent messages, questions and choices from the agent | never translated |
| Docs site (`sites/docs`) | English |

## Library and configuration

- `i18next` 26 + `react-i18next` ≥ 17.0.14, JSON v4, no other i18n
  library. Formatting goes through `Intl`.
- Web init, before `createRoot`:
  - `fallbackLng: "en"`, `supportedLngs: ["en", "cs"]`,
    `nonExplicitSupportedLngs: false`, `load: "languageOnly"`.
  - `partialBundledLanguages: true`; `en` of the `common` namespace is
    bundled; everything else comes through
    `i18next-resources-to-backend` with a dynamic `import()`.
  - `react: { useSuspense: false }`.
  - `interpolation.escapeValue: false` (React escapes).
  - `returnEmptyString: false`, `returnNull: false`.
  - `keySeparator: "."`, `nsSeparator: ":"` set explicitly.
- Server init: all languages loaded synchronously (`initAsync: false`,
  JSON imported), `escapeValue: true`. Code never calls
  `changeLanguage` on the server; every call site takes
  `i18n.getFixedT(locale, ns)`.
- One shared module creates both instances: `apps/server/shared/i18n/`
  holds `locales/{en,cs}/<namespace>.json`, the generated key types and
  `createI18n()`. The web imports it through the existing
  `server/shared` alias. Exactly one copy of `i18next` is installed.
- Keys are typed with `CustomTypeOptions` and
  `enableSelector: "optimize"`; call sites use the selector form
  `t($ => $.composer.send)`. Types are generated by `i18next-cli types`
  from the English catalog.

## Catalog

**Namespaces** follow the lazy chunks:

| Namespace | Loaded |
|---|---|
| `common` | eagerly; app shell, navigation, gates, sidebar, dialogs, shared labels, formats |
| `node` | with the detail pane |
| `files` | with the detail pane |
| `chat` | with the `SessionChat` chunk |
| `graph` | with the `GraphView` chunk |
| `settings` | with the settings page |
| `errors` | eagerly; one message per error code (server, desktop, web) |
| `server` | server only: handoff file, OAuth pages, default names |
| `desktop` | desktop only: menu item, loopback page |

A lazy chunk loads its code and namespace together:
`lazy(() => Promise.all([import("./X"), i18n.loadNamespaces("x")]).then(([m]) => m))`.

**Keys** are semantic, dotted, in English, and name where the text
lives: `composer.send`, `thread.state.running.chip`,
`files.conflict.count`. An English sentence is never a key.

**Rules for messages**

1. One key per complete sentence. No joining translated pieces with
   `+`, template literals or arrays. Placeholders are named
   (`{{nodeName}}`) so a translation can move them.
2. One key per context. A button "Open" and a status "Open" are two
   keys even when the English matches.
3. A translated noun is never interpolated into a sentence. Where the
   sentence depends on a node type, state or role, there is one message
   per value, or i18next `context` (`key_project`, `key_process`).
4. Counts use plurals: `key_one`, `key_other` in English;
   `key_one`, `key_few`, `key_many`, `key_other` in Czech (`many` is
   decimals, `other` is 0 and 5+). `count` is always a number.
5. Markup inside a sentence uses `<Trans>` with named components
   (`"Open <link>settings</link>"`). `t()` output never reaches
   `dangerouslySetInnerHTML`.
6. Typography lives in the translation: Czech „…“ quotes, non-breaking
   spaces, final casing. No `text-transform` and no `toUpperCase()` on
   translated text.
7. No keys built from runtime values (`t(\`state.${s}\`)`). An enum maps
   to keys through a complete `Record<Enum, key>` checked by the type
   system.
8. Anything that comes from the agent, the user or the data is passed
   as a placeholder value, never as a key. Agent output in the chat
   carries `translate="no"`.
9. Every placeholder and every ambiguous message has a translator note
   in `locales/_notes.json` (key → note).

**Glossary.** `apps/server/shared/i18n/glossary.md` fixes the English
term for every product concept (Práce, Předat, Pozastavit, Uzavřít,
uzel, mirror, runner, workspace, osobní / týmový workspace, vlákno,
...). A catalog entry uses the glossary term.

## Locale resolution

- Source of truth: `users.locale` (`"en" | "cs" | NULL`).
- Order: account → window cache → OS language (`navigator.languages`,
  first supported primary subtag) → `en`. `cs-CZ` resolves to `cs`.
- Window cache: localStorage `portuni:<ws_id>:locale`. It is per window
  because each workspace window can belong to another account.
- Boot (`main.tsx`): read the cache synchronously, init i18next with it,
  `await` the `common` and `errors` namespaces of that language, set
  `document.documentElement.lang`, then `createRoot`. No text renders
  before this.
- After `/me` answers: when `locale` differs from the cache, write the
  cache and `changeLanguage` (no reload). `NULL` in the account keeps
  the resolved language and does not write the account.
- Changing the language in Settings → Account: `PATCH /me` with
  `{ locale }`, then cache, `changeLanguage`, `lang` attribute, and
  the `set_ui_locale` Tauri command.

## Formatting

- Values inside a sentence use i18next formatters
  (`{{when, datetime}}`, `{{n, number}}`, `{{ago, relativetime}}`,
  `{{items, list}}`).
- Values standing alone (table cells, chips, the date picker) use
  `apps/web/src/lib/format.ts`: `formatDate`, `formatDateTime`,
  `formatRelative`, `formatNumber`, `formatTokens`, `compareText`,
  `weekInfo`. Each takes the locale, caches its `Intl` instance per
  locale and options, and replaces every local `fmtDate`,
  `relativeCzech`, `formatCzech`, hardcoded `"cs-CZ"` and
  `localeCompare(..., "cs")`.
- Server timestamps (`YYYY-MM-DD HH:MM:SS`, UTC) are parsed as UTC in
  one helper before formatting.
- The date picker takes month and weekday names from
  `Intl.DateTimeFormat` and the first day of the week from
  `Intl.Locale#getWeekInfo` (fallback: Monday for `cs`, Sunday for
  `en`).

## Server

**Errors.** Every error the web can show carries a stable `code` and
optional `params`: `{ error, code, params?, request_id? }`. `error` is
English and meant for logs. The web renders `errors:<code>` with
`params`; an unknown code shows the generic `errors:UNKNOWN` plus the
request id.

- Codes are derived from typed errors only. The places that pick a code
  by matching substrings of English messages (agent router, sessions
  route, sessions WebSocket) switch to typed errors before any message
  text changes.
- `SessionHandoffError`, `LocalModeNoRemoteError`, runner-instance
  errors and the constraint errors raised by triggers get codes and
  English messages.
- The runner model catalog returns a description code, not a sentence.

**Persisted events.** Question-card titles, runner error events and deny
messages shown in the chat are stored as `{ code, params }`, rendered by
the web. A stored event without a code (written before this change) is
shown as stored. A deny message returned to the agent as a tool result
is English.

**Text the device writes for a person.** The handoff summary file and
the default thread name use the locale of the request that causes them:
the web sends `locale` with `POST /sessions`, message sends, Předat and
Pokračovat v nové session. The device formats with
`getFixedT(locale, "server")`. Nothing on the device reads the locale
from process state or from the central server.

**Server-rendered pages.** The OAuth consent page and login error pages
use `users.locale` when the user is known, otherwise `Accept-Language`,
otherwise `en`; `<html lang>` matches.

## Data model and routes

- `users.locale TEXT NULL` with a check for `('en','cs')`: a new
  libsql migration, the same column in `PG_BASELINE_DDL`, carried by
  `db-export`/`db-import`. The personal workspace's single user gets
  the column through the same migration.
- `GET /me` returns `locale`. `PATCH /me` accepts `{ locale }`, scope
  `read` (a user changes only their own row).
- In a team workspace `/me` and `PATCH /me` are graph routes: the
  desktop proxy sends them to the central server; they are not
  device-local routes. The device needs no `CentralClient` method for
  the locale.

## Desktop

- Rust holds one app-wide `ui_locale` set by the `set_ui_locale`
  command from the focused window; the menu is rebuilt when it changes.
  The `Quit` item and the loopback login pages are rendered from the
  `desktop` namespace JSON embedded at build time.
- Every `Err(String)` the webview can show becomes an error code (with
  params) that the web renders from `errors`.
- `tauri.conf.json` declares `CFBundleLocalizations` `en`, `cs`.

## Third-party UI

- Streamdown: `translations` prop from `chat`.
- CodeMirror: `EditorState.phrases` from `common`.
- shadcn and AI Elements components: every default label (`Close`,
  `Loading`, `Stop`, `Submit`, branch navigation, tool states, empty
  state) is passed from the catalog; no English default remains in our
  copies.

## Tooling and the gate

`i18next-cli` (config `i18next.config.ts`) and a pseudo-locale.

`scripts/agent-gate.sh` and `ci.yml` run:

1. `i18next-cli extract --ci --dry-run`: fails when source keys and the
   English catalog differ.
2. `i18next-cli lint`: fails on a hardcoded user-facing string in JSX
   text or in `title`, `placeholder`, `aria-label`, `alt`, `label`
   attributes, and on concatenation of translated text.
3. `i18next-cli status cs`: fails on a missing or empty Czech value,
   including a missing plural form.
4. `i18next-cli status --unused`: fails on an unused key.
5. A catalog test: placeholders and `<Trans>` tags match between `en`
   and `cs` for every key; every plural key renders for `count` 1, 2,
   5, 1.5 in `cs` without falling back.
6. A grep check: no Czech diacritics in `apps/web/src`,
   `apps/desktop/src` or `apps/server` outside `locales/`, the
   glossary and comments.

**Pseudo-locale** `pseudo` (dev builds only, selectable in Settings):
a postProcessor that wraps each message in `⟦…⟧`, adds diacritics and
pads by 35 %.

## Tests

- Tests run with `lng: "en"`, `initAsync: false`, and assert English
  text or keys. Existing tests that assert Czech are rewritten to
  English.
- Pure helpers in `apps/web/src/lib` that need text take a `t`
  parameter; tests pass the English `t`.

## Workspaces

| | Team workspace | Personal workspace |
|---|---|---|
| Where `users.locale` lives | central server db | local db, the single user |
| `/me`, `PATCH /me` | central server via the desktop proxy | local server |
| Handoff file, default thread name | sync agent, locale from the request | local server, locale from the request |
| OAuth pages | central server | not used |

Both columns hold before an issue in this work closes.

## Rollout

1. **Spike** (throwaway): selector types under TypeScript 7, catalog
   HMR under Vite 8, one catalog imported by web and server, measured
   main-chunk delta.
2. **Foundation**: shared i18n module, web init and boot order,
   `format.ts`, gate checks (lint in warn mode), pseudo-locale,
   glossary.
3. **Server codes**: typed errors replacing substring matching, codes
   and params on every user-facing error, persisted events as code +
   params, model descriptions.
4. **Web migration by namespace**: `common` + gates, `node`, `files`,
   `chat`, `graph`, `settings`, `errors`. English copy is written new;
   Czech moves from the current source. Lint switches to failing when
   the last namespace lands.
5. **Account**: `users.locale`, `/me`, `PATCH /me`, the language picker,
   locale on session requests.
6. **Server text and desktop**: handoff file, default thread name, OAuth
   pages, Rust error codes, `set_ui_locale`, `CFBundleLocalizations`.
7. **Docs**: `sites/docs` quotes the English UI labels.
